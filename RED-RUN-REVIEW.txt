Root cause: stage 2 assumes `[enc] + enc.overflowing` from `tok.enable_truncation(510, stride=0)` covers the whole text. It covers about the first 508 tokens plus a fragment. No assertion checks coverage. The one test for it is masked because its repetitive pad is itself a classifier false positive. So every input past about 2.5k chars is judged on its head only, and the window cap and the "highest window wins" claim do not run as documented. Fix: tokenize once without truncation, slice the ids into 508-token windows with overlap (stride >= 64), and assert coverage. Add K1 as a planted case.
